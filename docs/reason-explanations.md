# 빈 Reasons의 중립 안내

2026-10-18부터 새로 실행하는 운영 분석은 analyzer의 원본 `reasons=[]`인 경우에만
확정된 점수 구간과 신호 가용성을 설명한다. 구체적인 감점 근거를 추측하거나 추가하지 않는다.
기존 이유가 있으면 기존 코드 순서와 Groq 자연어화·실패 fallback을 그대로 사용한다.

## 처리 흐름

`analyze_reviews()`의 확정 v0.5 결과 → 내부 설명 컨텍스트 복사 → 기존 Groq 후처리
→ 원본 이유가 비어 있던 결과만 중립 안내 → 기존 MySQL 저장 → JSON/SSE 반환.

- Groq는 원본 이유가 없는 리뷰를 계속 건너뛴다. 중립 안내에는 외부 LLM 호출이 필요하지 않다.
- Groq 비활성화·오류·timeout과 관계없이 빈 원본 이유의 중립 안내를 제공한다.
- 일반 JSON, 공식 POST SSE, 기존 실험 SSE는 공통 분석·저장 함수를 사용한다.
- `rti`, `level`, 세 점수, 식별자, 버전 및 필드 구조는 변경하지 않는다.
- `reasons`는 계속 `list[str]`이며 구체적인 analyzer 근거 또는 중립 안내를 담을 수 있다.
- DB 저장 실패 시 정상 결과를 반환하지 않는 기존 순서와 실패 정책을 유지한다.

## 안내 의미

| 기존 level / 가용성 | 안내 |
| --- | --- |
| safe | 계산 가능한 신호에서 높은 점수 구간. 구매 여부·후기 진위를 보장하지 않음 |
| warn | 주의 점수 구간. 구체적인 위험 근거가 별도로 제공되지 않아 추가 확인 필요 |
| danger | 낮은 점수 구간. 점수만으로 허위 후기·광고성 리뷰라고 단정하지 않음 |
| 세 신호 전부 -1 | 현재 정보와 계산 가능한 신호만으로 점수 산정 어려움 |
| 일부 신호 -1 | 계산 가능한 항목만 사용했으며 계산 불가 항목을 0점으로 반영하지 않았다는 추가 안내 |

가용성은 기존 wire contract의 `score != -1`을 그대로 사용한다. 실제 `0`점은 가용 신호다.
점수·등급·RTI 가중치·재정규화는 다시 계산하지 않는다. `-1`의 원인이 모델 로딩 실패 등일
수도 있으므로 모든 unavailable을 실제 사용자 정보 부족이라고 단정하지 않는다.

## 내부 인터페이스와 향후 AI 담당자 규격

`app/services/reason_explanations.py`의 `build_explanation_context()`는 원본 이유를
불변 tuple로 복사하고 RTI, 기존 level, 신호별 점수·가용성을 frozen dataclass에 보존한다.
`neutral_reasons(context)`는 이 컨텍스트를 읽고 문구만 만든다. 입력 점수나 원본 근거를
수정하지 않는 이 인터페이스를 향후 AI 담당자의 구조화된 설명 규격에 맞춰 확장할 수 있다.

현재 컨텍스트는 요청 처리 중의 내부 데이터이며 외부 응답, Groq payload, DB schema에
새 필드를 추가하지 않는다. DB에는 기존처럼 최종 API JSON만 저장하므로 원본 코드의
별도 영구 감사 저장소를 새로 만드는 작업은 포함하지 않는다. AI 담당자가 실제 관측 근거와
RTI 기여도 규격을 확정하기 전에는 독자적인 근거·기여도·감점 규칙을 만들지 않는다.

설명 정책의 내부 버전은 `neutral-summary-v1`이다. 점수 정책 `rti-v0.1`, 모델 버전,
계약 `v0.5`는 유지한다. 설명 버전은 현재 wire/DB 필드에 추가하지 않으므로 향후 문구 변경을
개별 저장 결과에서 추적해야 한다면 별도 메타데이터 계약·저장 방식을 협의해야 한다.

## 과거 데이터 및 Idempotency

과거 JSON과 기존 DONE 결과를 자동 수정하지 않는다. 동일 Idempotency-Key의 DONE replay는
저장된 결과만 읽으며 모델·Groq·중립 안내를 재실행하지 않는다. 따라서 과거 `reasons=[]`는
계속 빈 배열로 전달될 수 있다. 새 안내를 적용하려면 별도로 합의한 재처리 작업이 필요하다.
기존 키 삭제나 자동 재분석은 수행하지 않는다.
